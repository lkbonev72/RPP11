## Четим код: преди и след

| Преди | След |
|---|---|
| `def calc(a, b, c):` | `def final_price(price, discount_pct, vat_pct):` |
| `x1 = 0; tmp = []` | `total = 0; valid_orders = []` |
| `if x > 0:` … 40 реда … | `if x <= 0: return None` (ранно връщане) |

## Как се чете traceback

Стартирайте `demo/traceback_primer.py`:

```
Traceback (most recent call last):
  File "traceback_primer.py", line 26, in <module>
    pechatay_smetka([("банан", 2), ("круасан", 1)])        <- 4. откъде е тръгнало
    ~~~~~~~~~~~~~~~^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
  File "traceback_primer.py", line 22, in pechatay_smetka
    print(f"Сума: {suma(porachka):.2f} лв.")
                   ~~~~^^^^^^^^^^
  File "traceback_primer.py", line 17, in suma
    total += cena(produkt) * broy                          <- 3. кой го е извикал
             ~~~~^^^^^^^^^
  File "traceback_primer.py", line 11, in cena
    return CENI[produkt]                                   <- 2. ТУК гръмна
           ~~~~^^^^^^^^^
KeyError: 'круасан'                                        <- 1. ЕТО какво стана
```

Четем **отдолу нагоре**: първо какво е станало, после къде, и чак после кой е стигнал дотам. Знаците `^^^^` (Python 3.11+) показват точния израз на реда.

Обърнете внимание: програмата гърми в `cena`, но причината не е там. Причината е в поръчката, където „кроасан“ е написано с „у“. **Мястото на грешката и причината за нея често са различни неща.**

## Трите инструмента

| Инструмент | За какво | Кога НЕ го използваме |
|---|---|---|
| `breakpoint()` | искам да видя всички променливи в даден момент | в код, който ще се предава или пуска автоматично |
| `logging` | искам следа какво е правила програмата, без да я спирам | за еднократно надникване — там е по-бързо с дебъгер |
| `assert` | твърдя, че дадено състояние е невъзможно | за проверка на потребителски вход — там се вдига изключение |

### Команди на дебъгера

| Команда | Какво прави | Команда | Какво прави |
|---|---|---|---|
| `n` | следващ ред (без влизане във функции) | `p име` | отпечатва стойността |
| `s` | следващ ред (влиза във функцията) | `pp име` | отпечатва подредено |
| `c` | продължава до следващия breakpoint | `l` | показва кода наоколо |
| `w` | къде се намирам (стекът от извиквания) | `q` | изход |

В `demo/debug_demo.py` има закоментиран `breakpoint()`. Махнете `#` и опитайте командите.

## Git: минималният набор за тази година

```
git status                     # какво е променено (изпълнявайте често!)
git add .                      # подготвя всичко за запис
git commit -m "Добавена проверка за празен списък с оценки"
git push                       # качва комитите във вашия fork в GitHub
git log --oneline              # историята накратко
git log --oneline -- .         # историята само на текущата папка
git diff                       # какво съм променил след последния комит
git restore fail.py            # отказва НЕкомитнатите промени във файла
git revert --no-edit HEAD      # отменя последния комит с нов комит
git show HEAD~2:./fail.py      # показва файла отпреди 2 комита, без да променя нищо
```

**`restore` или `revert`?** `git restore` е за промени, които още не сте комитнали. `git revert` е за комит, който вече е в историята: не го изтрива, а добавя нов комит, който го отменя. Историята остава честна, а никой друг, който вече има вашия код, не се обърква.

> **Правило за съобщенията на комитите.** Съобщението отговаря на въпроса „какво прави този комит“, с глагол или причастие отпред:
>
> ДА: „Добавена обработка на празен списък с оценки“ · „Поправена сортировка в класацията“ · „Разделен vsichko.py на три модула“
>
> НЕ: „промени“ · „asdf“ · „работи“ · „финална версия 2 final ново“
>
> Проверка: след половин година ще можете ли да намерите този комит само по съобщението?

## Задача 4.1. Лов на молци (задължителна, ~20 мин)

Папка: [`4.1-lov-na-moltsi/`](4.1-lov-na-moltsi/)

*Внимание: поправката на първия дефект може да предизвика нови грешки на други места. Те не са нови дефекти, а последици от същата причина.*

**Изисквания към начина на работа:**

- Първия дефект намерете чрез traceback. Опишете как го прочетохте.
- Поне два от останалите намерете с `breakpoint()`, не с `print`. Запишете кои променливи сте проверили.
- Поне един намерете чрез разсъждение: пресметнете наум кой трябва да е първи в класацията и какъв е средният успех на класа, после сравнете с изхода.

Попълнете таблицата в `defekti.md`. **Оценява се колоната „Причина“, не колоната „Поправка“.**

## Задача 4.2. Историята на един файл (задължителна, ~10 мин)

Папка: [`4.2-istoriyata-na-edin-fail/`](4.2-istoriyata-na-edin-fail/)

Работите във вашия fork, който вече е Git хранилище. Затова тук **не** се прави `git init`. Изпълнявайте командите от тази папка.

1. Копирайте поправения си `buggy_grades.py` тук като `grades.py`. Направете комит с работещата версия.
2. Добавете функция `median(grades)` и направете втори комит.
3. Умишлено счупете `average`, например заменете `len(grades)` с `len(grades) - 1`. Направете комит със съобщение, което ясно казва, че това е експеримент.
4. Стартирайте. Програмата дава грешни числа. Отменете експеримента с `git revert --no-edit HEAD` и проверете, че числата отново са верни.
5. Променете нещо в `grades.py`, **без** да комитвате, и го върнете с `git restore grades.py`.
6. Запишете изхода на `git log --oneline -- .` в `otgovor.md`, отговорете на въпросите там и направете `git push`.
