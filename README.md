## Как да започнете

### 1. Направете си копие (fork)

Влезте в GitHub, отворете това хранилище и натиснете **Fork** горе вдясно. Получавате собствено копие на адрес `https://github.com/<вашето-име>/RPP11`.

### 2. Изтеглете копието на компютъра (clone)

```
git clone https://github.com/<вашето-име>/RPP11.git
cd RPP11
```

### 3. Кажете на Git кои сте (веднъж на компютър)

Без тази стъпка първият комит на нов компютър завършва с грешка `Please tell me who you are`.

```
git config --global user.name "Име Фамилия"
git config --global user.email "имейлът-ви-от-github@example.com"
```

### 4. Работният цикъл

```
git status                      # какво съм променил
git add .                       # подготвям промените
git commit -m "Добавена проверка за празен списък"
git push                        # качвам в моя fork в GitHub
```

Правете комит след всяка завършена стъпка, а не веднъж в края на часа.

### 5. Когато учителят добави нови материали

Отворете своя fork в GitHub и натиснете **Sync fork → Update branch**. След това на компютъра:

```
git pull
```

## Автоматични проверки

Някои задачи имат файл `test_*.py`. Той проверява дали функциите ви правят това, което изисква условието. Проверките се пускат така:

```
# веднъж: среда в корена на хранилището и инсталиране на pytest
python -m venv .venv
.venv\Scripts\activate             # Windows
source .venv/bin/activate          # macOS / Linux
python -m pip install -r requirements.txt

# всеки път: проверка на една задача
python -m pytest urok-2-funkcii-danni-izklyucheniya/2.4-dnevnik -v
```

Преди да сте написали решението, проверките **трябва** да се провалят. Целта е всички да станат зелени.

> Зелените проверки не са оценка. Те показват, че функциите връщат верните стойности за подготвените примери. Учителят оценява и как е написан кодът, и дали можете да го обясните.

## Правила за цялата година

- `.venv/` никога не влиза в Git. Файлът `.gitignore` в корена вече се грижи за това.
- Всеки файл се отваря с `with` и с явно `encoding="utf-8"`.
- Съобщението на комита казва **какво прави** комитът: „Поправена сортировка в класацията“, а не „промени“ или „asdf“.
- Прехващайте най-конкретното изключение, което можете да назовете, върху най-малкия блок код, който може да го предизвика.
- Генеративен ИИ може да се използва като помощник, но вие трябва да можете да обясните, тествате и поправите всеки ред от кода си. Учителят може да посочи произволен ред и да поиска обяснение.

## Помощ за Windows

| Проблем | Решение |
|---|---|
| `python` не е намерен | Опитайте `py` вместо `python` (например `py -m venv .venv`) |
| `Activate.ps1 cannot be loaded because running scripts is disabled` | В PowerShell изпълнете `Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass` и активирайте отново. Другият вариант е да работите в `cmd` |
| `where python` в PowerShell не показва нищо | В PowerShell `where` е друга команда. Използвайте `where.exe python` или `Get-Command python` |
| `requirements.txt` изглежда странно след `pip freeze >` | Windows PowerShell 5.1 записва с `>` в UTF-16. Изпълнете командата в `cmd` или използвайте `python -m pip freeze \| Set-Content -Encoding utf8 requirements.txt` |
